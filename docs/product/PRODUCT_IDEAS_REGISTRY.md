# Korixa — Registro de Ideas de Producto

## PRODUCT_IDEAS_REGISTRY.md

- **Fecha de creación:** 2026-07-31
- **Creado por:** Ejecutor técnico documental (tarea de sincronización de estado del proyecto).
- **Propósito:** registro vivo y permanente de ideas de producto de Korixa (anteriormente RidePro), para que ninguna decisión o idea quede perdida al reordenar prioridades. **No sustituye** a `docs/audits/AUDITORIA_FINAL/BACKLOG_MAESTRO.md`, que es una auditoría técnica congelada y no se modifica bajo ningún concepto.
- **Relación con el backlog técnico:** cuando una idea de este registro pasa a ejecución, recibe un ID de backlog (`T-F<fase>.<n>` o `T-NEW.<n>`, según `RIDEPRO_DEVELOPMENT_PROTOCOL.md` §8) y ese ID se anota en la columna "Última decisión" de la idea correspondiente — la idea sigue existiendo aquí, con su estado actualizado a "En ejecución"/"Implementada", nunca se borra.

---

## Reglas del registro

1. **Ninguna idea se elimina.** Una idea que deja de perseguirse cambia de estado a "Aplazada", "Bloqueada" o "Descartada con justificación" — nunca se borra de este documento.
2. **Una idea aplazada cambia de estado, pero permanece registrada**, con la fecha y el motivo del aplazamiento.
3. **Una decisión nueva no puede reemplazar silenciosamente una anterior.** Si una idea nueva reemplaza el enfoque de una idea anterior, la idea anterior se marca "Descartada con justificación" (citando la idea que la reemplaza) — no se edita como si nunca hubiera existido.
4. **Todo cambio de estado incluye fecha, estado, motivo y relación con tareas técnicas** (columna "Última decisión").
5. **Este registro no sustituye `BACKLOG_MAESTRO.md`** — el backlog técnico es la fuente de verdad de qué se ejecuta y en qué orden dentro de lo ya auditado; este registro es la fuente de verdad de qué ideas de producto existen, independientemente de si ya tienen o no una tarea técnica asociada.
6. **Cuando una idea pasa a ejecución, recibe un identificador de backlog** (ver "Propósito" arriba) y esa referencia se registra aquí.
7. **No se inventan fechas de implementación ni costes.** Una idea sin evidencia de priorización real se marca "Propuesta" o "En análisis", nunca con una fecha estimada fabricada.

## Estados posibles

| Estado | Significado |
|---|---|
| **Aprobada** | El propietario aprobó la idea explícitamente, sin que la ejecución técnica haya comenzado todavía. |
| **Propuesta** | Idea registrada, sin análisis técnico ni decisión de negocio todavía. |
| **En análisis** | Existe al menos una decisión de diseño/arquitectura documentada (punto de extensión, dependencia identificada), sin implementación de código. |
| **Aplazada** | Se decidió explícitamente no perseguirla ahora; permanece registrada para retomarla más adelante. |
| **Bloqueada** | No puede avanzar por una dependencia externa (técnica o de decisión del propietario) no resuelta. |
| **En ejecución** | Tiene una tarea técnica activa asociada (ID de backlog) y avance real, aunque incompleto. |
| **Implementada** | Completada y verificable en el código/CI actual. |
| **Descartada con justificación** | Se decidió no perseguirla, con el motivo explícito documentado. |

## Cómo leer la columna "Evidencia u origen"

Cita un archivo/documento/PR/commit real del repositorio cuando existe, o indica explícitamente **"idea nueva, sin documentación previa"** cuando la idea se registra por primera vez en esta tarea — nunca se afirma una fuente que no se verificó.
